# Obsidian sync conflict repair

`05. Docs` is generated by the repository bridge. Folder Notes must not create
or rename notes there, and Waypoint must not rewrite its exported documents.
Keep both plugins available for ordinary author-owned notes elsewhere.

The [November 5 repair](../../docs/evidence/2026-11-05-obsidian-sync-conflicts.md)
records the observed race, installed fix, cleanup, recovery directories and limits.
The bridge's application code remains owned by `openhands-symphony`; this helper
owns client sync configuration and conflict recovery only.

## Protect generated documents

Inspect live sync state first. `repair-sync-conflicts.py protect` prepares three
changes: a recursive Folder Notes exclusion for `05. Docs`, Waypoint ignore
patterns for that tree and conflict filenames, and a guard in Waypoint's shared
writer. Waypoint **3.0.1** ignores paths when detecting markers but bypasses that
check during parent-index updates; settings alone do not prevent writes. The
patch is pinned to the verified installed source hash and refuses another build.

```bash
python3 clients/obsidian/repair-sync-conflicts.py protect \
  --vault /Users/rafael/Obsidian/obsidian-cloud-retrieval \
  --recovery /Users/rafael/.local/state/dothomelab/obsidian-conflicts/NEW-protection
python3 clients/obsidian/repair-sync-conflicts.py apply \
  --recovery /Users/rafael/.local/state/dothomelab/obsidian-conflicts/NEW-protection
obsidian plugin:reload id=folder-notes
obsidian plugin:reload id=waypoint
```

Use the intended active vault for the Obsidian CLI, or supply its `vault=` option.
Verify with an isolated folder beneath `05. Docs`: no same-name note should be
auto-created; adding/removing a child must leave an existing Waypoint note's bytes
unchanged. Remove that exact disposable folder afterward. Normal folder notes
and Waypoint outside the exclusion must remain enabled.

Plugin updates can replace `main.js`. After a Waypoint update, inspect whether
the upstream writer now honors ignored paths and repeat the live regression
check. Do not remove the exclusions or blindly patch an unrecognized version.
Other Obsidian devices must receive the settings/plugin file and reload the
affected plugins before editing generated docs. Syncthing syncs these plugin
files; it does not reload an already-running plugin on another device.

## Plan and review cleanup

```bash
python3 clients/obsidian/repair-sync-conflicts.py plan \
  --vault /Users/rafael/Obsidian/obsidian-cloud-retrieval \
  --recovery /Users/rafael/.local/state/dothomelab/obsidian-conflicts/NEW-cleanup
```

This reads all filenames containing `sync-conflict`, including derived cache
names and retained local versions. It saves byte-exact, SHA-256-verified blobs
and `plan.json` outside the vault. The directory is mode 0700 and blobs are 0600;
they may contain private notes or historical plugin credentials. Never commit,
print or sync these payloads. Review the manifest without dumping content.

The plan restores a generated conflict body only when its normal document
contains nothing except recognized navigation/template material. Differing
candidate bodies stop planning. Other old settings, calendar versions and notes
remain in the recovery archive; they never overwrite current working files.
Only dead conflict-link lines inside generated Waypoint blocks are removed.

After reviewing the exact scope and confirming the writer fix:

```bash
python3 clients/obsidian/repair-sync-conflicts.py apply \
  --recovery /Users/rafael/.local/state/dothomelab/obsidian-conflicts/NEW-cleanup
```

Apply verifies every blob and every before-image before its first mutation,
then rechecks each file immediately before writing/deleting. Concurrent edits
stop the run; already applied entries retain their recovery bytes. Do not retry
a partially applied plan blindly. Confirm zero conflicts in the live vault and
connected peers after their scans finish. Preserve offline peers' state; their
deletions are verified only after they reconnect. This is scoped file recovery,
not a whole-vault backup or a guarantee against future concurrent user edits.

## Restore one archived file

Choose its exact `path` from the relevant `plan.json`:

```bash
python3 clients/obsidian/repair-sync-conflicts.py restore \
  --recovery /Users/rafael/.local/state/dothomelab/obsidian-conflicts/NEW-cleanup \
  --path 'exact/manifest/path.md'
```

Restore refuses to overwrite subsequent changes. Restoring old conflict names
reintroduces them to sync, so extract/read a blob privately when only comparing
an old version. Keep the recovery directories until Rafael has reviewed the
cleanup and all intended peers have synchronized; removal needs explicit scope.

Run `python3 clients/obsidian/test_repair_sync_conflicts.py` for recovery integrity,
concurrent-edit, symlink, ambiguous-body and document-preservation checks.
