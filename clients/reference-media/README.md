# Saved references on the Mac

This client archives Instagram Saved posts and Yaay saves while the Mac is
awake, then publishes private metadata into the existing local Obsidian vault.
Excalidraw is the primary board format; Canvas remains supported. Media Extended
renders the immutable server files inside note embeddables. Reference Boards
adds independent excerpt/frame commands, paused starts and playback coordination.

## Use

Open or create a private Excalidraw or Canvas board in Obsidian, then use the
command palette's **Reference Boards: Add a reference to this board**.
Choose **Instagram → Grind** (or another source/collection). Folders open one
level at a time; breadcrumbs and **Back** move up the real source hierarchy.
Folder search covers the displayed level. A folder shows its immediate children
and its own posts, without combining descendants into its counts. Browse one thumbnail
entry per source post; select a post to see its carousel members and a paused,
seekable server preview. Cached video transcripts appear below the player with
scrollable text, clickable timestamps and quality warnings. Opening or refreshing
a preview only reads cached evidence; transcript errors do not block playback. Choose **Full video** or **Excerpt**, name the card,
and add it. Start/end controls switch to Excerpt; full video resets the bounds. **Choose excerpt or capture frame on this board** changes one
card or captures its current frame. Each addition creates an independent note;
copying the same note manually to another board deliberately shares that note.
Removing a card does not delete its note or canonical media. Native Excalidraw
notes, arrows and file embeddables support mind maps and itinerary cards.

`References/Archive` shows inventory/import status and links to collections.
`Sources` and `Collections` contain importer-owned blocks; annotations outside
those blocks survive refresh. `Projects`, drawings and `Frames` are user-owned
and never regenerated by catch-up. Collection names are display metadata, so
renames and reparenting do not move originals or break project references.
Demo boards and acceptance exports are optional; the installed examples were
removed after review. Keep `Catalog.json`, thumbnails and the generated library
notes. Removing a whole `References` folder also removes saved work and breaks
the browser until its catalog is restored. The agent-brief command needs no board.

Videos are acquired eagerly by the collector, independently of opening boards.
The picker filters exact source/collection IDs before applying text search.
Independent memberships are listed separately; Yaay parent/child paths remain
hierarchical. Current contents and removed memberships are separate views.
Pending, partial and retrying posts remain visible with explicit acquisition
status; they count as posts, not carousel files. Shared Instagram/Yaay identities
produce one post entry, retaining all memberships and immutable media references.

Default order is the source collection grid order. **Published: newest/oldest**
uses verified Instagram publication timestamps, with unknown dates last, never
download time. Yaay's save creation time is retained separately; older catalogs'
Yaay `source_created` values are not treated as publication dates.
The source grid order is not asserted to be a saved timestamp: Instagram can
reorder saves, and no saved-at timestamp is exposed by this contract.

Videos start paused. Switching posts/members or closing the browser stops its
player; board, editor and picker players share the same single-player policy.
If Media/VPN is offline, local thumbnails and metadata remain visible; the
preview reports the connection error and disables adding unavailable media. Full media stays outside the vault; only metadata, boards,
small JPEG thumbnails and selected still frames sync. Keep `References` outside
blog publication inputs: do not embed/link its private content from Blog articles.
The `private` field is descriptive; the existing blog exporter follows selected
article references, so it is not an access-control flag.

## Installation and authentication

Requirements: macOS, Chrome, Python 3, Homebrew FFmpeg, the existing local vault,
Media Extended and Excalidraw community plugins, and an enrolled
[restricted server endpoint](../../hosts/infra/reference-media/README.md).
Pinned acquisition dependencies are in `requirements.txt`.

The support directory is `~/Library/Application Support/dothomelab-references`
(mode 0700), outside Git and Syncthing. It holds the Chrome profile, scoped SSH
key, checkpoints, retry state and retained releases. Chrome uses its normal
macOS Keychain integration. Cookies are passed to gallery-dl only in memory;
no exported cookie file, storageState file, credentials in URLs or raw HTTP logs.

To enroll a new client, generate one dedicated Ed25519 key there, install only
its public key on the endpoint, and verify the PVE host key through the normal
SSH trust flow. Never give the collector a root key. Then create its virtualenv,
install the pinned requirements and sign in through:

```bash
"$HOME/Library/Application Support/dothomelab-references/venv/bin/python" \
  clients/reference-media/browser-session.py \
  --profile "$HOME/Library/Application Support/dothomelab-references/browser-profile"
```

Sign in to Instagram and Yaay, then close that separate browser. The helper
holds the collector lock during human sign-in; an active job must finish first.
Renew expired sessions the same way. Normal chat-browser sessions are unrelated.

From a committed checkout, install with actual deployment values:

```bash
python3 clients/reference-media/install.py \
  --vault /absolute/path/to/local-vault --host PVE_ADDRESS \
  --instagram-saved-url https://www.instagram.com/YOUR_ACCOUNT/saved/ --enable
python3 clients/reference-media/install-obsidian.py \
  --vault /absolute/path/to/local-vault --archive /Volumes/Media/references
```

For an existing collector, `python3 clients/reference-media/install.py --enable`
reuses its private configuration. This Mac-only update needs no server contact
or endpoint deployment and preserves the inventory checkpoint and download queue.

Enable Reference Boards in Community plugins once; toggle it off/on after an
update. Install the [Media reconnect helper](../macos-media/README.md) for home
and the inspected private VPN route. The installer never changes vault sync or
installs an offline video cache.

## Catch-up and completeness

Initial backfill runs every ten minutes while awake, advancing at most eight
Instagram pages and acquiring up to twelve pending posts. During that initial
phase, completed Yaay scans refresh hourly and Instagram scans after six hours.
Once both inventories have completed and every queued post is archived or has
a recorded acquisition failure, the worker automatically switches to daily mode.
Failed originals stay visible and retryable; they are not declared archived.

Daily mode performs one fetch session per 24 hours, scanning both inventories
and acquiring up to twelve pending posts. It completes Instagram pagination in
that session instead of splitting a normal daily inventory across many days;
interrupted scans retain their cursor for the next daily run. Existing retry
backoff still applies. A larger backlog after several days away drains in later
daily batches, without returning to frequent polling.

The existing LaunchAgent `media.rafael.reference-collector` checks local due time
at login and every ten minutes while awake. Between daily sessions it exits
without SSH, browser/source requests or vault writes. It never wakes the Mac;
an overdue session starts on the next awake check, without replaying missed days.
The due time is saved before I/O, so a failed daily attempt also waits until the
next day. `References/Archive` shows the active schedule and next fetch time.
Source changes during root enumeration restart the inventory without discarding
its preceding submitted snapshots.

To finish a particular inventoried Instagram collection without waiting behind
the wider library, run a scoped acquisition from the committed checkout:

```bash
"$HOME/Library/Application Support/dothomelab-references/venv/bin/python" \
  clients/reference-media/worker.py \
  --support "$HOME/Library/Application Support/dothomelab-references" \
  --instagram-collection 18071229254573049 --batch 45
```

This selects current members by exact ID, skips unrelated inventory work and
leaves the normal daily due time unchanged. It shares the collector lock and
returns without work if a scheduled batch is active. Existing retry cooldowns
and the two-failure circuit breaker still apply; inspect Archive and verify
receipts/files instead of assuming process exit means every post was acquired.

For an explicitly requested whole-library finish, use the same command with
`--finish-backfill` instead of `--instagram-collection ... --batch ...`. This
finishes source pagination and attempts every pending original once, including
previous failures. It records only safe HTTP status/count diagnostics, continues
past individual incomplete originals, and stops on source access/rate failures.
It does not erase retry history, fabricate receipts or change an existing daily
due time. A later retry still needs a healthy authenticated source.

If an Instagram original is unavailable but the same post has retained media in
Yaay, acquisition uses that saved copy and records its provenance in the receipt
and picker. Carousel IDs with numeric source positions retain that order; missing
members cannot be silently accepted as a complete post. Missing/generic CDN
content-type headers are checked against file signatures; saved videos must also
pass FFprobe with a video stream and positive duration before upload.

Yaay uses observed authenticated web synchronization from a fresh browser
context: explicit initial checkpoints, connected pagination, terminal pages,
root UI parity and both China boards' visible section headings. Native IDs,
weights, repeated memberships, empty lists, metadata and source URLs are retained.
The observed web schema exposes boards and sections; deeper recursive trees pass
fixtures, but native-app levels absent from the web sync cannot be inferred.

Instagram enumerates the visible Saved collection grid independently of media
downloads, including cards loaded while scrolling. gallery-dl supplies Saved and
collection pagination; explicit `more_available`/cursor validation is required.
Every collection, including All Posts, is also scrolled to a stable, non-loading
end, accumulating virtualized cards. Its exact IDs and order are compared with the API, and visible
UI-only posts enter acquisition with unknown publication dates until source
metadata is available. API-only discrepancies preserve both observations and
keep the scan partial for retry; they never retire old membership. Root completion
alone does not establish per-collection completeness. A failed/empty ambiguous
grid keeps the scan incomplete. Collection audits show source counts and times.
Unfiled membership is computed only after every collection completes. Saved
soundtracks in Instagram's separate Audio picker are not Saved image/video posts.

A partial/failed scan never retires previous memberships. Complete scans mark
absent memberships inactive but keep history and media. Acquisition is marked
complete only after every returned image/video carousel member has a verified
upload/link receipt. Two failures pause acquisition for an hour; individual
retries back off to seven days. An unavailable original is retained as a source
record, not an empty import. No deletion operation exists on the archive endpoint.

Temporary download members are removed after completion acknowledgement; failed
work stays private for retry. Inspect retained files before manual cleanup; never
remove canonical objects to reset the queue. Logs contain counts/error classes,
not raw downloader exceptions. `worker-state.json` and `References/Archive` expose
last success, phase and delayed retries. A sleeping/offline Mac cannot report a
fresh heartbeat; timestamps are part of interpreting status.

## Verification and rollback

```bash
python3 -m unittest discover -s hosts/infra/reference-media -p 'test_*.py'
"$HOME/Library/Application Support/dothomelab-references/venv/bin/python" \
  -m unittest discover -s clients/reference-media -p 'test_*.py'
node --test clients/reference-media/obsidian/test*.cjs
launchctl print "gui/$(id -u)/media.rafael.reference-collector"
```

`import-sample.py` repeats a bounded real sample, verifies carousel receipts and
generates thumbnails. It is an operator acceptance tool, not the ongoing scheduler.
`create-example.cjs` is a one-time installer that refuses existing files; source
refresh never invokes it. The dated [delivery evidence](../../docs/evidence/2026-11-02-reference-media-boards.md)
distinguishes actual playback/import checks from fixtures and pending remote work.

Pause future runs with `launchctl bootout
"gui/$(id -u)/media.rafael.reference-collector"`; use this when the worker is idle
unless intentionally interrupting a job. A stopped/incomplete upload is retried;
canonical objects are never overwritten. Retained release directories include
`DEPLOYED_COMMIT`. Restore the prior LaunchAgent plist from the support directory
and bootstrap it to roll back client code. Do not roll back the catalog database
or remove downloaded media. Plugin replacements are retained under
`rollback/<timestamp>/reference-boards`; restore that folder and toggle the plugin.
The read-only mount helper has its own timestamped binary/plist backups.

## Reconcile a disputed collection

Capture a sanitized observation from the authenticated source API and visible
collection grid: exact native IDs (preserve 64-bit IDs as strings), source keys,
media members, publication timestamps and ordered membership. Do not export
cookies, raw HTTP responses or signed CDN URLs. `reconcile.py --help` describes
the observation format. Its read-only default compares every post with the live
archive and writes an acquisition report; `--apply` submits a partial snapshot
for that collection and republishes metadata without retiring any memberships.

```bash
"$HOME/Library/Application Support/dothomelab-references/venv/bin/python" \
  clients/reference-media/reconcile.py \
  --support "$HOME/Library/Application Support/dothomelab-references" \
  --observed /private/path/collection-observed.json \
  --report /private/path/collection-report.json
# Add --apply only after reviewing identity/order/count differences.
```

[November 4 reconciliation and picker acceptance](../../docs/evidence/2026-11-04-reference-collection-browser.md)
records all 45 Grind identities, source order, media types, acquisition status
and the limits of explaining the preceding 38-post inventory.

## Agent context and provider settings

The third command, **Create an agent brief from videos**, works without a board.
It uses the same source/folder browser, thumbnail grid and preview as board-add.
Click a card to preview; check **Include this video** (or **Video N** for a
carousel) below the player. Checking never changes the preview or starts playback.
Images cannot enter the video selection. The current preview stays visible when
browsing other folders; navigation pauses playback. Native buttons and checkboxes
support Tab, Enter and Space. Selection persists across previews, search, sorting
and folder/source navigation, deduplicated by asset ID, up to 50 videos.

The bottom **Selected videos** list stays visible. Click a title to preview that
exact video. Drag its left-hand menu handle to another row to reorder, or focus
the handle and press Up/Down. Individual removal and **Clear selection** also remove
those videos' captured frames. Closing the browser discards this unsaved selection.

The optional task field and actions remain below the list. **Copy text** copies
Markdown containing the task, ordered transcripts, timestamps, source links,
quality warnings and chosen-frame timestamps. Paste it into a browser agent, then
use **Copy images** and paste again. A clipboard holds the latest copy: paste text
before copying images. Image export is one PNG sheet labeled by episode and time,
containing only frames explicitly chosen with **Capture this frame** below a
selected video's preview (up to 50 frames). Seek to another moment to add a frame;
remove unwanted frames using their thumbnail controls. Frames are stills, not full
videos or automatic visual analysis. Image-only copying does not require speech.

Cached evidence is checked automatically. **Request / refresh transcripts**
explicitly queues or checks selected videos through the existing scoped SSH
connection. Text copying and saving require every selected transcript; pending or
retry results are never silently omitted. **Save agent brief** writes private
Markdown and JSON provenance under `References/Briefs`, plus the PNG sheet when
frames were chosen. The note embeds that sheet; attach the PNG separately when
uploading to an agent that does not resolve Obsidian embeds. No files are created
by the clipboard actions. Final selection order controls episode numbering in all
outputs. The existing board commands retain their excerpt/frame workflow.

Three independent provider settings cover storage/retrieval, speech-to-text, and
video understanding. Only local storage and server-side Whisper are implemented.
The local visual option uses existing captured frames; attach them explicitly to
a vision-capable agent. Hosted options are disabled, with no credentials accepted
or network fallback. A release adding hosted providers must implement each
independently, validate connections before replacing working settings, and keep
recoverable user secrets in the OS keychain rather than vault JSON or logs.

`install-obsidian.py` bundles both pure models, retains the preceding plugin, and
points the plugin at the existing private collector connection file. The service
API key never reaches the Mac. The command only exports evidence; agent dispatch,
repository access, VM computer use and merge policy remain the agent system's job.

For an operator or automated test, `context.py --support <collector-support>
--source-key instagram:<id> [--source-key ...] --request` prioritizes selected
videos. The same command with `--output <private-json-file>` exports complete
cached context. It fails when any selection is not ready. Server enrichment is
independent of the awake-only source-fetch schedule and never starts local ASR.
